## 0. 五条结论

1. **60% 的分数（AI 深度 35% + 创新 25%）买的是「可被指认的 AI 工程」，不是「用了 AI」。** 规则原文对 RAG 的要求是「生成质量因检索显著提升」（规则 4.2），这是可测量的断言，必须有基线/优化后的对照数字。
2. **35% 里真正难的是 8% 的 Agent 和 6% 的 RAG，最容易白丢的是 4% 的 MCP 和 4% 的安全。** 后两项成本低、评委辨识度高，是性价比最高的补分点。
3. **创新性的 25% 必须落在「路径生成机制」上，不能落在「加了个聊天框」。** 自适应学习的现有产品（ALEKS、Khanmigo、松鼠 AI）已经占了「AI 辅导」这个位置，正面撞车等于放弃 10% 的选题创新。
4. **剩下的 40%（前端 10 + 实用 10 + UX 10 + 社会 10）是工程卫生与叙事，多数队伍会丢。** 这 40% 里没有一项需要新算法，只需要证据：指标截图、试点数据、对比度检测、成本模型。
5. **决赛答辩占决赛总分 30%**（规则 4.5），且规则明写「选手须能解释所有代码逻辑」（规则「八、比赛环境·特别说明」）。所以从第一天起，每个技术点都要留下「能讲 90 秒」的素材，否则国赛会被打回。

## 1. 评分表复核：权重结构说明了什么

| 维度 | 权重 | 子项拆解 | 判分性质 |
| --- | --- | --- | --- |
| AI 技术深度 | 35% | 8 + 8 + 6 + 5 + 4 + 4 | 可验证的工程证据 |
| 创新性 | 25% | 10 + 8 + 7 | 主观，靠对比与命名 |
| 前端工程质量 | 10% | 4 + 3 + 3 | 可量化（CWV / Lighthouse / TS） |
| 实用性 | 10% | 5 + 5 | 靠试点数据 |
| 用户体验 | 10% | 4 + 3 + 3 | 半主观，有 WCAG 硬指标 |
| 社会价值与商业潜力 | 10% | 5 + 5 | 叙事 + 单位经济模型 |

**读法**：AI 深度这一行是「做了没有」，创新/实用/社会这三行是「说得清没有」，前端与 UX 两行是「查得到没有」。三类证据的准备方式完全不同，不能混在一起做。

**一个反推**：若目标省赛一等奖（各省 ≤10%，规则 7），按加权 80 分倒推，一个自洽的配额是：AI 深度 86/100（加权 30.1）、创新 76/100（19.0）、前端 80/100（8.0）、实用 80/100（8.0）、UX 80/100（8.0）、社会 70/100（7.0），合计 80.1。反过来看，AI 深度从 86 掉到 60 分，直接少 9.1 分——相当于把创新性整项的 36% 让掉，且无法靠 UX 或文档补回来。

## 2. AI 技术深度 35%：逐项的可验收证据

### 2.1 大模型集成质量（8%）

| 必须出现 | 常见失分 |
| --- | --- |
| **模型路由表**：`lib/ai/models.ts` 里按任务列映射（诊断用强推理模型、批改用小模型、结构化输出用支持 strict 的模型），而非全局一个 `model` 常量 | 全项目一个 `chat.completions.create`，换个模型要改 20 处 |
| **结构化输出 + schema 校验**：诊断报告、路径节点、题目全部走 JSON Schema（OpenAI Structured Outputs 保证遵守 schema，但 refusal 与 token 截断仍会破坏结构，必须处理 `refusal`/`incomplete` 分支）（developers.openai.com/api/docs/guides/structured-outputs） | 用正则从自由文本里抠 JSON；没有失败分支 |
| **Prompt 版本化**：`prompts/*.ts` 带版本号 + 固定评测集快照，文档里能贴 v1→v3 的 diff 与指标变化 | Prompt 硬编码在组件里，无法回溯 |
| **成本与延迟工程**：长 system prompt 开 prompt caching（缓存读 0.1× 基础输入价，5 分钟写入 1.25×，最小可缓存长度按模型 512–4096 token）（platform.claude.com/docs/en/docs/build-with-claude/prompt-caching） | 每轮重发完整上下文，token 成本失控且首字延迟高 |
| **流式**：SSE 输出、首 token 时间（TTFT）可测（AI SDK 5 已将 SSE 定为标准流式协议）（vercel.com/blog/ai-sdk-5） | 等全文生成完再一次性返回 |

### 2.2 Agent / 工作流设计（8%）

| 必须出现 | 常见失分 |
| --- | --- |
| **可数的状态图**：诊断 → 定标 → 生成路径 → 出题 → 批改 → 重规划，节点在代码里显式（LangGraph 的 state / node / edge，支持 checkpoint 与 human-in-the-loop）（docs.langchain.com/oss/python/langgraph/overview） | `while (true) { llm(); }` 冒充 Agent |
| **至少一个真自主决策**：根据答题表现决定「继续 / 回退先修 / 换表征（图→例题→口述）」，且决策可回放 | 固定 if-else 流程包装成「Agent」；反过来，该用 workflow 的地方硬上 Agent 导致错误累积（Anthropic 明确建议多数场景单次优化调用即可，Agent 仅在无法硬编码路径时使用）（anthropic.com/engineering/building-effective-agents） |
| **真工具**：查先修关系、查题库、算复习时点、写学习记录，每个工具独立可单测 | 工具函数里再调一次 LLM，无法单测 |
| **轨迹可视化**：每步 thought / action / observation 落库，前端能展开（ReAct 式循环）（arXiv:2210.03629） | 只有最终答案，演示时只能说「它自己会想」 |
| **边界**：最大步数、超时、单次会话预算上限 | 无上限，一次跑飞烧掉整月额度 |

> 策略：把「确定性步骤用 workflow、开放决策用 agent」的划分写进技术文档。这本身就是评委想看的判断力，比堆一个全自主 Agent 更安全（且不违反评分表——评分表给的是「Agent 或复杂 AI 工作流」，二者等价）。

### 2.3 RAG 技术应用（6%）

| 必须出现 | 常见失分 |
| --- | --- |
| **语料是课程知识图谱 + 教材/讲义切片**，不是通用百科；每个 chunk 带 `chapter / kp_id / 先修关系` 元数据 | PDF 直接切 1000 字丢进向量库 |
| **混合检索 + 重排**：BM25 + 向量召回 → rerank。Anthropic 实测 top-20 检索失败率 5.7% → 仅上下文嵌入 3.7%（−35%）→ 加上下文 BM25 2.9%（−49%）→ 加重排 1.9%（−67%）（anthropic.com/news/contextual-retrieval）；BEIR 的结论是「BM25 是稳健 baseline」，而 dense/sparse 检索器在零样本跨域上常弱于 rerank 与 late-interaction 模型（arXiv:2104.08663） | 只做余弦相似度 top-k，没有 rerank |
| **chunk 语境前缀**：嵌入前给每块补 50–100 token 的上下文说明（同上 Anthropic 方法） | chunk 脱离章节后语义断裂 |
| **排序策略**：关键片段放头/尾。长上下文中段信息会被显著忽略（Lost in the Middle，arXiv:2307.03172） | 无脑塞 20 块，最重要的那块埋在中间 |
| **引用回链**：每个结论可点回原文片段 | 答案无出处，等于不可解释 |
| **离线评测集 ≥50 条 + 指标**：faithfulness = 被上下文支持的 claim 数 / 总 claim 数（docs.ragas.io faithfulness 页）；文档里给「基线 vs 优化后」两列数字 | 没有评测集，无法回应「生成质量因检索显著提升」这句评分原文 |

> 进阶（拿满 6% 的差异点）：**检索质量自评 + 纠错**。CRAG 用轻量评估器给检索结果打置信度，低置信时改走 web 搜索或分解重组（arXiv:2401.15884）；Self-RAG 用 reflection token 让模型决定「要不要检索」（arXiv:2310.11511）。实现其中一个即可在文档里写「我们的 RAG 有失败兜底」。

### 2.4 多模态能力（5%）

**选 2 个模态做深，不要 4 个都浅。** 对本题最自然的两条：

| 必须出现 | 常见失分 |
| --- | --- |
| **手写/拍照题目 → 结构化**：视觉模型识别 → 输出 `{题干, 选项, 知识点, 难度}` → 入库。必须带**置信度 + 人工确认**环节：MathVista 上 GPT-4V 总体准确率 49.9%，仍比人类低 10.4 个百分点（arXiv:2310.02255），直接信 OCR 会污染学生模型 | 上传框 + OCR 文本直接入库 |
| **语音问答**：Web Speech API 的 `SpeechRecognition` / `SpeechSynthesis`（developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API），或 Whisper（680,000 小时多语种弱监督，零样本接近人类鲁棒性）（arXiv:2212.04356） | 语音只用来 TTS 念答案，不进入学习闭环 |
| **融合**：两个模态的输出必须写回同一个学生模型（掌握度、错因标签），驱动同一条路径 | 多模态各玩各的，与路径规划无因果关系 |
| **浏览器端推理加分**：Transformers.js 默认 WASM、可选 WebGPU（标注为实验性），`q8` 为 WASM 默认量化（huggingface.co/docs/transformers.js） | 声称「端侧 AI」但实际全部走云端 API |

### 2.5 AI 安全与可控性（4%）

| 必须出现 | 常见失分 |
| --- | --- |
| **输入/输出双向过滤**：OpenAI Moderation 免费、13 类、支持文本+图像、**不支持音频**（developers.openai.com/api/docs/guides/moderation） | 只在 system prompt 写「你是安全的助手」 |
| **教学安全策略**：不直接给答案、不强化错误概念、必须给脚手架——正对应 SafeTutors 归纳的三类失败；且该基准发现长对话下教学失败率从 17.7% 升到 77.8%（EMNLP 2026，arXiv:2603.17373） | 只做通用内容审核，不做「教学行为」审核 |
| **长会话护栏**：每 N 轮强制小结 + 重新校准、教师/家长接管入口 | 单轮测试通过就认为安全（SafeTutors 明确指出单轮「安全/有帮助」会掩盖长程系统性失败） |
| **兜底路径**：模型超时/拒绝/限流 → 降级到规则引擎（按知识图谱先修关系出题）。演示时**真的拔掉 key 演一次** | 无降级，API 一挂全站白屏 |
| **可解释**：每个路径节点给出理由（先修满足度 / 掌握度 / 遗忘曲线位置），对应可解释知识追踪的透明模型与事后解释两条路线（arXiv:2403.07279） | 推荐理由是「AI 认为适合你」 |
| **合规**：《生成式人工智能服务管理暂行办法》2023-08-15 施行（www.gov.cn/zhengce/zhengceku/202307/content_6891752.htm）；AIGC 标识办法 2025-09-01 施行，要求显式+隐式标识（www.cac.gov.cn/2025-03/14/c_1743654684782215.htm） | 学生数据明文存 localStorage，无隐私说明 |

> 注意：React 错误边界**不捕获**事件处理器、异步代码、SSR 中的错误（react.dev Error Boundary 文档）。流式响应出错时它接不住——必须另有 `onError` + 重试 + 降级，这是「错误边界处理优雅」这条 3% 的实际含义。

### 2.6 MCP / 工具集成（4%）

| 必须出现 | 常见失分 |
| --- | --- |
| **真起一个 MCP server**，暴露三类原语：`tools`（查先修/查题/记成绩）、`resources`（课程大纲、知识图谱）、`prompts`（出题模板）。MCP 基于 JSON-RPC 2.0，传输支持 stdio 与 Streamable HTTP，最新规范为 2026-07-28 版（modelcontextprotocol.io/specification/latest） | 把普通 function calling 说成 MCP——评委里有 AI 行业从业者，一问 `tools/list` 就穿帮 |
| **客户端链路可见**：`createMCPClient` → `tools/list` → `tools/call`，日志或 MCP Inspector 里能截到 JSON-RPC 往返（ai-sdk.dev/docs/ai-sdk-core/mcp-tools） | 只有代码，没有可展示的协议层证据 |
| **生产部署用 HTTP/SSE，不用 stdio**：AI SDK 文档明确 stdio「cannot be deployed to production environments」 | 本地 stdio 跑通就宣称「可部署」 |
| **工具安全**：工具描述视为不可信输入；高风险工具要求人工确认。MCP 官方安全最佳实践列了 confused deputy、token passthrough、SSRF、session hijacking 等攻击面（modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices） | 无授权、无确认，工具直接执行副作用 |

> 背景可用：MCP 由 Anthropic 于 2024-11-25 开源（anthropic.com/news/model-context-protocol）。2026 版规范已改为无状态、每请求带 `_meta` 与 `server/discover`，且 `sampling` 原语被弃用——文档里写对这一句，能立刻区分「读过规范」和「抄的博客」。

## 3. 创新性 25%：怎么让「新」被看见

| 评分点 | 必须被看见的东西 | 常见失分 |
| --- | --- | --- |
| **选题创新（10%）** | 一句话说清四件事：**谁 / 什么场景 / 现在怎么做 / 我们改变了什么**。对本题的可用空白：现有路径推荐依赖专家标注的先修关系（成本高），且单条先修链会在学生卡壳时阻塞整条路径——KnowLP 正是以此立论，用「先修 + 相似」双图替代单一先修链（arXiv:2506.22303）。我们的差异点：~~用班级错题共现自动生成 similarity 边~~（已撤回，见上），改为**用 Beta 后验把掌握度的不确定度显式化 + 路径可被学生/教师改写 + 公开材料里未见三者同时成立** | 选题写成「大学生学习效率低」——范围大到无法证伪；创新点写成技术清单（「我们用了 RAG + Agent + 多模态」） |
| **技术方案创新（8%）** | **可命名的四层架构**：知识图谱（先修，Knowledge Space Theory：知识状态是技能子集，outer fringe 即「已具备学习条件的知识点」）（en.wikipedia.org/wiki/Knowledge_space）× 知识追踪（BKT 四参数：p-init / p-transit / p-slip / p-guess，隐马尔可夫，二值掌握）（en.wikipedia.org/wiki/Bayesian_knowledge_tracing；DKT 用 RNN 替代显式领域知识，arXiv:1506.05908）× 间隔重复（FSRS 的 DSR 模型：`R(t,S) = (1 + factor·t/S)^(-w20)`，S 为 R=90% 时的间隔，D 取值 1–10）（github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm）× LLM（解释、出题、批改）。每层职责单一、接口清晰，配一张分层图 | 四层揉成一个 prompt；无法回答「去掉 LLM 这套系统还能不能跑」（能跑，才是好架构） |
| **交互模式创新（7%）** | **反事实路径预览**：学生问「如果我今天只学 20 分钟 / 跳过这章会怎样」，系统即时重算路径并高亮差异（哪几个节点后移、哪个截止点会破）。这是列表式 LMS 做不到的，且天然适合录进演示视频 | 交互创新 = 换了个配色 / 加了打字机效果 |


> **⚠️ 「错题共现生成 similarity 边」已在 06 中撤回（2026-10-22）**：`06-synthesis.md` §2.2 判定，在本期规模（40 KC / 120 题 / n=30–60）下任意两 KC 的共现计数中位数为 0，估不出稳定相似度，因此**不做**。上表「选题创新」行的差异点已改为「Beta 后验显式化不确定度 + 路径可改写 + 公开材料未见三者同时成立」。

> 差异化必须点名对标：ALEKS 用知识空间理论做自适应评估（UC Irvine 1994 起，McGraw-Hill 2013 收购）（en.wikipedia.org/wiki/ALEKS）；Khanmigo 2023-03-14 上线、基于 GPT-4、$4/月，且 WSJ 实测其数学辅导会出现基础计算错误（en.wikipedia.org/wiki/Khanmigo）；松鼠 AI 把初中数学拆成 1 万+ 知识点，但「学习不由学生主导」，由系统决定顺序（en.wikipedia.org/wiki/Squirrel_AI，该条目带宣传语气警告）。**我们的差异点就写「学生可干预 + 反事实预览 + 可解释的推荐理由」**——正好补上松鼠 AI 的短板。

## 4. 前端工程 + 用户体验（合计 20%）：最容易白拿的分数

### 4.1 前端工程质量（10%）

| 评分点 | 必须出现 | 常见失分 |
| --- | --- | --- |
| 代码质量 4% | `tsconfig` strict；ESLint + Prettier 可复现；按 feature 分目录（`features/path/`、`features/diagnosis/`）；无大段 `any` | 只贴一张目录树截图，点进去组件 800 行 |
| 组件化 3% | 服务端状态用 TanStack Query、客户端状态用 Zustand，二者边界写进文档；路径图 / 题目卡 / 掌握度图各自独立可复用 | 所有状态塞进一个 Context |
| 性能 3% | Core Web Vitals 达标：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1（p75，移动+桌面）（web.dev/articles/vitals）；Lighthouse 性能分权重为 TBT 30% / LCP 25% / CLS 25% / FCP 10% / SI 10%（developer.chrome.com Lighthouse scoring）；给出优化前后对照 | 只报分数不报测法（哪台机器、哪个页面、几次取中位） |

### 4.2 用户体验（10%）

| 评分点 | 必须出现 | 常见失分 |
| --- | --- | --- |
| UI 4% | 设计 token 统一（Tailwind + shadcn/ui）；响应式三档；对比度 ≥4.5:1（大字 ≥3:1，WCAG 2.2 SC 1.4.3 AA）（w3.org/WAI/WCAG22/Understanding/contrast-minimum） | 深色模式对比度不达标 |
| 交互 3% | 路由切换有骨架屏：Next.js `loading.tsx` 自动包 `<Suspense>`，且**不包裹同层 layout**（nextjs.org/docs/app/api-reference/file-conventions/loading） | 每个页面自己写 loading 布尔值 |
| AI 交互 3% | ① 流式渲染；② 思考状态**分阶段可见**（「正在检索 3 个知识点 → 正在比对先修 → 正在生成路径」）；③ 可中断（stop）、可重生成（regenerate）；④ 错误态可重试。AI SDK 的 `status` 已定义 `submitted → streaming → ready / error` 四态，直接映射 UI（ai-sdk.dev/docs/ai-sdk-ui/chatbot） | 等待时只有一个转圈；流式输出导致 CLS 抖动 |

> 无障碍是便宜分：键盘可达（WCAG 2.1.1）、焦点可见、语义标签。改造成本低，且能在文档里写成「符合 WCAG 2.2 AA」——WCAG 2.2 于 2023-10-05 发布，并已成为 ISO/IEC 40500:2025（w3.org/WAI/standards-guidelines/wcag）。

## 5. 实用性（10%）与社会价值/商业潜力（10%）

| 评分点 | 必须出现 | 常见失分 |

| 场景真实性 5% | 真实课程大纲 + 真实题库（哪怕只做一门课一个班）；需求写成可证伪的句子：「XX 课程期中通过率 62%，主因是先修缺口未被识别」；附访谈/问卷原始记录 | 用「大学生学习效率低」当需求；题库全部由 LLM 现编 |

| 社会价值 5% | 用**成本论证公平**：一对一辅导的效果量级是「受辅导学生平均高于对照班 98% 的学生」（Bloom 1984 二西格玛问题，en.wikipedia.org/wiki/Bloom's_2_sigma_problem），但成本「多数社会无法大规模承担」——本作品把边际成本压到接近零。同时**主动交代效果边界**：ITS 元分析 50 项对照研究的中位效应量 d=0.66，但标准化测验上只有 0.13（Kulik & Fletcher 2015, Review of Educational Research；经 Wikipedia ITS 条目转引，未取得原文） | 只写「促进教育公平」 |
| 商业潜力 5% | 单位经济模型：每活跃学生每月 token 成本（用缓存读 0.1× 计价）× 活跃率 + 推理成本；B2B2C（高校/机构采购）+ 订阅；给出毛利区间与盈亏平衡点 | 「先免费后广告」；无任何数字 |

> 政策背书可引用（非必须）：《教育强国建设规划纲要（2024－2035年）》提出国家教育数字化战略、建设「人工智能教育大模型」（gov.cn，2025-01-19 新华社报道）。
