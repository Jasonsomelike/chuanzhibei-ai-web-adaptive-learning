## 二、命题范围

作品须为基于 AI 技术的 Web 应用，体现 AI 的深度应用，而非简单 API 调用。官方给出 10 个推荐方向，也可自拟。

1. AI Agent 智能助手
2. RAG 知识问答系统
3. 多模态 AI 创意平台
4. AI 协同办公工具
5. **AI 教育与学习平台** —— 含「AI 辅导教师、智能出题系统、**自适应学习路径规划**、编程教学 AI 助手」
6. AI 健康与生活服务
7. AI 代码开发辅助
8. AI 数据分析与可视化
9. AI 安全与内容治理
10. AI 社交与社区应用

选题要求：

- 须为原创，严禁抄袭或直接包装开源项目参赛
- 须以 Web 应用形态呈现（PC 端 / 移动端 Web）
- 须深度集成 AI，AI 功能是核心而非附属
- 鼓励关注社会价值、解决真实问题、具备落地潜力
- 鼓励创新应用方式，而非复刻已有产品

## 四、评审标准（核心）

### 4.1 维度与权重

| 评分维度 | 权重 | 核心考察点 |
| --- | --- | --- |
| AI 技术深度 | **35%** | AI 应用深度、集成质量与创新性 |
| 创新性 | **25%** | 选题创新、模式创新、交互创新 |
| 前端工程质量 | 10% | 代码质量、组件化架构、性能优化 |
| 实用性 | 10% | 真实场景价值、问题解决能力 |
| 用户体验 | 10% | UI/UX、交互流畅度、易用性 |
| 社会价值与商业潜力 | 10% | 社会意义、商业前景、可持续性 |

### 4.2 AI 技术深度（35%）细则

| 考察点 | 分值 | 评分标准 |
| --- | --- | --- |
| 大模型集成质量 | 8% | 合理选择并高质量集成 LLM，Prompt 精巧，输出稳定可控 |
| Agent / 工作流设计 | 8% | 实现 AI Agent 或复杂 AI 工作流，具备规划、工具调用、自主决策能力 |
| RAG 技术应用 | 6% | 实现 RAG 架构，检索策略合理，生成质量因检索显著提升 |
| 多模态能力 | 5% | 集成多种模态（文本、图像、语音、视频），融合自然 |
| AI 安全与可控性 | 4% | 输出安全、可解释、内容过滤与兜底机制 |
| MCP / 工具集成 | 4% | 通过 MCP 协议或 Function Calling 实现 AI 与外部工具/数据源集成 |

### 4.3 创新性（25%）细则

| 考察点 | 分值 | 评分标准 |
| --- | --- | --- |
| 选题创新 | 10% | 发现独特场景或未被满足的需求 |
| 技术方案创新 | 8% | AI 技术组合应用有新意，有独特技术方案 |
| 交互模式创新 | 7% | 人机交互方式创新，体验超越传统模式 |

### 4.4 其余维度细则

**前端工程质量（10%）**：前端代码质量 4%（TypeScript 规范、组件清晰、可维护、无明显 Bug）；组件化与架构设计 3%（组件划分合理、状态管理规范、模块解耦、可复用）；前端性能优化 3%（首屏、渲染性能、懒加载、代码分割、缓存）。

**实用性（10%）**：场景真实性 5%（面向真实需求，问题定义清晰）；解决方案有效性 5%（AI 方案真正解决问题，相比传统方案有明显优势）。

**用户体验（10%）**：UI 设计与视觉表现 4%（美观、布局、响应式、设计系统统一）；前端交互体验 3%（路由流畅、动画自然、反馈及时、加载状态优雅）；AI 交互体验 3%（流式输出渲染、AI 思考状态可视化、错误边界处理）。

**社会价值与商业潜力（10%）**：社会价值 5%（解决社会问题、促进公平包容、推动行业进步）；商业潜力 5%（商业模式、市场空间、可持续性）。

### 4.5 评分方式

- 各维度百分制，按权重加权得总分
- 评审组由高校教师、企业技术专家、AI 行业从业者组成
- 每件作品不少于 3 位专家独立评分，取平均分
- 决赛增加现场答辩评分（占决赛总分 30%）
- 设最低分数线；零分卷不得奖

## 五、省赛作品提交要求

### 5.1 代码仓库

| 要求项 | 具体要求 |
| --- | --- |
| 托管平台 | GitHub / Gitee，**须设为 Public 或提供评审访问权限** |
| 代码规范 | 结构清晰、有效注释、遵循主流规范 |
| README | 项目介绍、技术架构、安装运行指南、团队信息 |
| Git 记录 | 保留完整提交历史，体现真实开发过程 |
| 环境配置 | 完整说明，含环境变量模板、依赖清单 |

> 注意：省赛要求仓库 Public 或给评审开权限，因此「私有调研仓库」不能直接作为提交仓库，最终需另建公开仓库或开放访问。

### 5.2 演示视频

5–8 分钟；含项目介绍、核心功能演示、AI 技术亮点；MP4，≥1080p；普通话讲解，可配字幕。

### 5.3 技术文档

PDF，≤30 页；须含项目概述、需求分析、系统架构设计、AI 技术方案、核心功能实现、测试与部署、总结与展望。**须重点阐述 AI 技术选型理由、集成方式、优化策略**；**须明确列出技术创新点与应用创新点**。

### 5.4 在线演示（可选加分）

公网可访问地址；评审期间保持可用；如需登录须提供评审专用测试账号。

### 5.5 提交注意事项

- 全部材料经大赛官网统一提交
- API 密钥等敏感信息不得出现在公开仓库，须用环境变量
- 提交后不得修改
- 材料不完整影响评审

## 八、比赛环境（推荐技术栈，非强制）

### 前端框架

| 技术 | 推荐场景 | 特点 |
| --- | --- | --- |
| React + Next.js 14+ | 全栈 AI Web 应用（推荐首选） | App Router、Server Components、API Routes、流式渲染 |
| Vue 3 + Nuxt 3 | 渐进式 AI 应用、内容型平台 | Composition API、SSR/SSG、自动导入 |
| Svelte 5 + SvelteKit | 轻量高性能 AI 应用 | Runes 响应式、内置路由 |
| React + Vite | 单页 AI 应用 | 快速开发、HMR |
| Astro | 内容驱动型 AI 应用 | 零 JS 默认、岛屿架构 |

### UI 与样式

Tailwind CSS（强烈推荐）、shadcn/ui、Ant Design / Element Plus、Framer Motion / GSAP、Three.js / React Three Fiber。

### 前端 AI 交互集成

| 技术/SDK | 用途 |
| --- | --- |
| Vercel AI SDK | 流式对话、Tool Calling、生成式 UI（推荐首选） |
| LangChain.js | 浏览器端 LLM 链式调用、轻量 Agent |
| Transformers.js | 浏览器端本地模型推理（端侧 AI） |
| WebGPU / ONNX Runtime Web | 高性能浏览器端 AI 计算 |
| Web Speech API | 语音输入/输出 |
| MediaPipe | 实时图像/视频 AI 处理 |

### AI 模型接入

- 大语言模型：OpenAI API、Anthropic Claude API、Google Gemini API、智谱 AI API、DeepSeek API
- 多模态：GPT-4o、Gemini Pro Vision、通义千问 VL
- 图像生成：DALL·E 3、Stability AI API
- 语音：Whisper API、TTS API

### 状态管理与数据层

Zustand / Jotai / Pinia、TanStack Query、IndexedDB / LocalStorage、WebSocket / SSE。

### 开发工具推荐

Cursor、GitHub Copilot、Windsurf、Figma、v0.dev、Storybook、Git、pnpm、ESLint + Prettier + TypeScript。

### 特别说明

- 以前端 Web 应用为主要呈现形态，后端仅作 AI 接入层，不是考察重点
- 鼓励用 Next.js API Routes / Nuxt Server Routes 简化后端
- 允许使用 AI 辅助编程，但选手须能解释所有代码逻辑
- 商用 AI API 费用自理，鼓励用免费额度
- 鼓励浏览器端推理（Transformers.js、WebGPU）体现端侧智能
- 涉及用户数据须合规、做好隐私保护
