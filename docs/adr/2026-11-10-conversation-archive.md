# 完整课程导师会话档案

存储、导师界面及教学工作流均已接入。

## 记录与模型上下文分开

旧版 `learning_sessions` 保存每个账号、每门课程的最后一个检查点和四轮短文本。旧接口继续提供这些记录，导师通过明确的旧版记录入口读取。新会话存入 `tutor_conversations` 与 `tutor_messages`，教学路由按当前会话读取最近四轮文本与教学状态。

消息按轮次保存完整正文、引用原文快照、上传资料摘录、网络引用、图片和展示状态。图片沿用当前上传流程的 JPEG 压缩结果，按提问保存。读取使用序号游标与字节预算，不裁剪已保存正文，也不把整段会话反复上传。

数据库先按消息体积筛选，再把一页内容传回服务端；接口另行校验实际响应体积。列表按置顶、更新时间及稳定 ID 分页，避免深页 OFFSET。归档与回收站均保留原始消息。

## 版本与分支

追加一轮的提问、回答占位及会话版本检查在同一条 SQL 中完成；幂等消息 ID 支持网络重试。修改回答使用单条消息版本，不覆盖另一窗口的新结果。

分支在同一条 SQL 中新建会话并复制所选回答之前的完整前缀，保留图片和原文快照。继承记录只读，分支之后的新问答独立追加；原会话不受影响。未完成的回答不能作为分支点。

## 教学证明

客户端只能写内容字段，不能提交工作流、判分或服务端身份。教学检查点与核验过的作答结果放在单独的 `proof` 列，通过服务端函数写入，运行令牌与课程约束共同限定写入范围。晚到的生成更新不能擦掉已保存的判分结果。

每个查询和写入都使用登录会话提供的账号 ID；不接受请求体中的账号归属。接口要求同源写入，响应禁止缓存。分支继承的练习不得直接再次提交为学习证据。

## 执行与验证

生产环境继续使用 Neon Postgres；本地内存实现逐条对应具名 SQL。新增的 PGlite 仅是开发依赖，在真实 PostgreSQL 执行层验证同一组 SQL 的追加、版本冲突、回滚、分页、分支和证明边界，不进入前端或线上运行路径。

数据库迁移为 `0003_tutor_conversations.sql`，由结构一致性测试与应用内幂等建表规则共同校验。历史旧检查点没有保存过的文字或图片不能重建；界面接入时需保留明确的旧记录说明。

未登录的会话存入独立的 IndexedDB，账号会话从服务端读取。界面提供历史搜索、重命名、置顶、归档、回收站恢复、按回答创建分支、图片原图预览和引用快照阅读。切换账号或会话后，旧请求的页面更新失效。用户停止生成会清除服务端运行令牌，使晚到的回答无法写回。

作答请求携带会话与回答标识，服务端核对该轮练习并保存首次判分结果。另一场对话启动后仍可回到原轮作答，恢复时沿用当时保存的证据数与路径结果。

参考：[PostgreSQL 数据修改 CTE](https://www.postgresql.org/docs/current/queries-with.html#QUERIES-WITH-MODIFYING)、[JSON 编码约束](https://www.postgresql.org/docs/current/datatype-json.html)、[PGlite API](https://pglite.dev/docs/)。
